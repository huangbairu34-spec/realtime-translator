## 实时翻译软件（Windows / YouTube 等外语直播字幕）
- 需求：抓取系统播放音频 → 本地 Whisper 识别 → 云端 LLM 翻译 → 悬浮字幕；中日英互译；RTX 4060 显卡。
- 技术栈：soundcard(回环) + faster-whisper(CUDA) + OpenAI 兼容接口 + PyQt6。
- 环境：Python 3.13 隔离 venv（`C:\Users\85098\.workbuddy\binaries\python\envs\default`）。
- **关键坑**：Windows 上 ctranslate2 缺 `cublas64_12.dll`，必须额外装 `nvidia-cublas-cu12` + `nvidia-cudnn-cu12`，并在 asr.py 里 `os.add_dll_directory` 注册 `site-packages/nvidia/*/bin`。
- 实测性能（RTX 4060, medium/float16）：RTF≈0.056，33.6s 音频推理 1.87s，远超实时。
- 结构：main.py 入口；src/ 下 config/audio_capture/vad/asr/translator/subtitle_window/history_window/settings_dialog/pipeline。
- 三个窗口：悬浮字幕条（置顶半透明，可拖/滚轮调字号/鼠标穿透）+ 独立对话记录窗口（历史回看、导出TXT）+ 设置面板。
- 待用户操作：填 API Key、选音频设备；`启动.bat` 双击运行。

## 实时性优化（第二轮：用户反馈"能出但明显滞后"）
- 根因诊断：旧版是"等整句 + 静音判定后才识别 + 一次性翻译(2.09s)"的串行批处理，总延迟 3~5s。
- 重构为**流式增量架构**：
  - `pipeline.py` 重写：capture 线程只管填缓冲；stream 线程每 interval_ms(默认900ms) 对"当前句缓冲"做增量识别；translate 线程流式翻译逐字上屏。
  - 事件模型 `SubtitleEvent(kind=partial|final)`：partial 实时刷新悬浮条，final 才写历史（避免重复）。
  - 句末检测频率与识别间隔解耦：120ms 高频检测静音→快速定稿。
  - `_drain_latest` 合并积压，跳过过时 partial，避免浪费 API。
  - 定稿识别为空时，用最后的 partial 文本兜底定稿（防"说过了没留下"）。
- 实测：首字延迟 636ms→**319ms**，定稿 1469ms→**980ms**，DeepSeek 流式首字 **588ms**（一次性为 2090ms）。
- 配置新增 `streaming.*` 段与 `translate.stream/speculative`；默认模型 medium→**small**，beam_size 2→1（贪心解码）。
- **发现并修复**：config 里 `translate.model` 原为 `deepseek-flash`（无效），改为 `deepseek-chat`。
- 设置面板新增"识别间隔""句末静音判定""流式/增量预览翻译"选项。
- 测试脚本 `test_streaming.py`（stub ASR 测纯架构延迟，可复跑）。
